# Auris / BitChord 3.0.31 — checklist

Continues 3.0.30 (see `3.0.30-CHECKLIST.md`; A–E there are done and shipped in
the `v3.0.30-draft`). This release carries two reports:

1. **Apple Music addon** — lossless / hi-res / Dolby stutter and buffer.
2. **Automix** — "this guy's phone is putting the entire song in automix,
   sometimes refusing automix analysis" (device: samsung SM-S948B, Android 17;
   log `/tmp/a3fa9ad2-…txt`).

---

## F. Apple Music addon

**F1. The analyser measured the master.** — FIXED
- Cause: the analyser asked the source for the *player's* quality. Twelve
  seconds of a 24-bit/44.1 master is 6.7MB, and it arrived at 29.7s on the
  link the track was already streaming over. Its ending wanted thirty seconds
  more — 16.8MB and another 36.8s — and both went into the *player's* cache
  entry, so the analyser and the player were downloading the same file at the
  same key at the same time.
- Fix: `SourceResolver.analysisCopy` asks for `StreamRequest.Best` (≈320kbps)
  — 480kB for the same twelve seconds — and `AudioCache.ensureAnalysisCopy`
  fetches it under its own sibling key `<source>|<track>#analysis`. The
  player's entry is never written to by the analyser.
- Verify: the log line `analysis copy of <id>: …kB … at 320 kbps`.

**F2. Read-ahead filled the whole master.** — FIXED
- Cause: `AudioCache.prefetchSourceTrack` looped to the end of the file —
  78MB of a lossless master, two and a half minutes of background traffic on
  the link the previous track was streaming over. That is where the stutter
  was made of.
- Fix: `MAX_SOURCE_PREFETCH_BYTES` (8MB) bounds it. The hand-over needs a few
  seconds of audio; the rest streams live at the rate the player needs it.

**F3. "Upgrade quality" did nothing on a source-backed track.** — FIXED
- Cause: `QualityUpgrade.forcedStream` keyed its record by the `v` query
  parameter. A source-backed track's URI carries none — its identity is
  `src:<config>::<track>` — so the upgrade was found, parked, auditioned and
  then never served.
- Fix: keyed by `mediaIdIn(uri)`. The recovery path clears the same key.

**F4. Every re-open re-ran the whole source ladder.** — FIXED
- Cause: the resolver branch had no memory of what it had already answered,
  so one catalogue row cost three walks of the ladder — the wait on a radio
  tap.
- Fix: `StreamChoice` pins one stream per track, however many times the player
  opens it, and a source turned off afterwards does not keep serving.

**F5. Spotify catalogue rows were fetched by id alone.** — FIXED
- Cause: the read-ahead built a URI from the row's id, with no title in it, so
  the name-matched lookup found nothing and cached nothing.
- Fix: the row's own URI carries the name; the fast `substituteForYouTube`
  path replaces the 20-second patient search for a catalogue row.

## G. Automix

**G1. The phone put the entire song into Automix.** — FIXED
- Cause: the forced analysis round pulled the *whole track* — the log says
  `analysis head round for 7EQvkYX9if4: total=7040679 want=7040679` — up to
  16MB, on the same link the listener was hearing the track over. Nothing
  marked the copy as the analyser's either, so a whole song per analysed
  track stayed on the device.
- Fix: the analysis round asks for a *window* (twelve seconds, 4MB ceiling);
  the tail round asks for thirty seconds at the end. The whole-track pass
  still runs, on a copy that is already whole. The analyser's copies are
  tagged, so the purge drops them.

**G2. The analysis was refused: "decoded 12.0s of a 221.0s (container — cached
with holes?)".** — FIXED
- Cause: a bounded fetch is answered with a response that describes the
  *range*, and the cache recorded that range as the resource's length. A
  one-megabyte head was therefore filed as a complete one-megabyte track, the
  analyser read it as complete, and the whole-track pass decoded twelve
  seconds of a three-and-a-half-minute song and refused it. Three of those
  and the track was written off for the session.
- Fix: `AudioCache.recordContentLength` corrects a length that is smaller than
  the truth (and is called after the fetch, when the entry exists);
  `TrackAnalyzer.isAnalysable(duration)` refuses a copy too short to *be* the
  track; `TrackAnalyzer.structure` treats an incomplete copy as "not all here
  yet" rather than as a broken file, so it costs no strike and throws nothing
  off disk.

**G3. The panel drew the whole song as the Automix box.** — FIXED
- Cause: `automixWindow` fell back to `contentEnd` when the plan had no window
  of its own — which is every pair the planner had not decided, and every pair
  it refused — and the start of that fallback was zero. The box was drawn from
  the start of the song to the end of its content: the entire song, marked as
  the blend.
- Fix: with no plan, the box is the last four bars of the content; with no
  analysis at all, it is empty.
