## A. Spotify search (reported: empty, "not even an error")

**A1. Search returns no rows and no reason.** — ROOT CAUSE FOUND, FIXED
- The diagnostic named it on the first try:
  `answered by assistedCurationSearch (tracks=8 albums=8 artists=8 playlists=0
  top=8); 10 tracks, 0 playable; 0 rows`.
- Spotify answered. Ten tracks came back. **All ten were then thrown away**
  because none of them matched a playable copy — the search was drawing
  matches, not Spotify's catalogue. A catalogue row that no source holds is
  still a real row.
- [x] Root cause: matching was a condition for *appearing*.
- [x] The diagnostic stays, and now reads `N tracks, N rows`.

**A2. Spotify rows are Spotify rows.** — FIXED
- Every track Spotify returns is drawn, with the id `spotify:<id>`.
- Playback: the player asks the enabled sources for the recording by name
  (title/artist/duration/album, already in the media URI) and pins the answer.
  YouTube is asked only when it is switched on and no source holds it. A track
  nothing holds fails as a track that cannot play — which is the truth, and
  better than a search that pretends the song does not exist.
- Radio/Flow still find the Spotify id: the row registers it on the way in.

## B. Flow (reported: no mix at full discovery, locked on Spotify, no persistence, crowded tuner, cheap UI)

**B1. Discovery at 100% builds no mix** — FIXED
- Cause: the seed pool was hard-gated at ≥0.85 discovery to drop every
  favourite *and* every played track. A Spotify seed pool is exactly those two
  lists, so the pool emptied, the local pass returned early, and the mix was a
  blank page. Below 0.85 the gate was off, which is why it "worked" there.
- Fix: the pool is not gated; familiar tracks are removed from the *finished*
  queue instead, and an empty local pass falls through to expansion rather than
  returning early. Never returns an empty mix while seeds exist.

**B2. "Like N more songs to start your endless mix" on the Spotify catalogue** — FIXED
- Cause: unlock counted YouTube likes; on the Spotify provider that count is 0.
- Fix: Flow unlocks when Spotify is the selected provider.

**B3. Every install means building a fresh Flow** — FIXED
- Cause: the stored mix was keyed on `BuildConfig.VERSION_CODE`, so every
  update deleted it. The snapshot's *shape* is what matters, not the build.
- Fix: shape version only.

**B4. Tuner is crowded — twenty genre chips** — FIXED
- Fix: ten chips, "Show N more" expands, collapse returns; the block animates
  its height instead of jumping.

**B5. "Flow" appears twice in the Flow screen** — FIXED
- Cause: an uppercase eyebrow label above the title that also says Flow.
- Fix: eyebrow removed; the title stays.

**B6. Flow feels cheap — no motion** — FIXED
- Hero fades and rises in; the subtitle crossfades when the mood changes; the
  track count animates instead of snapping; the chosen mood chip leans forward
  on a spring; Play presses into the surface; the tuner unreels; the genre block
  resizes smoothly; the mix reorders with `animateItem` instead of jumping.

## C. Preload / Automix (reported: effects fire, next track never loads)

**C1. YouTube off ⇒ next track is never prepared.**
- The read-ahead asks `SourceResolver.prepareForPlayback` for the next track and
  pins the stream it gets — but the call is wrapped in `runCatching`, so a
  cancellation is reported as a failure ("next-track preparation failed …:
  StandaloneCoroutine was cancelled") and the prepared stream is thrown away.
  With YouTube off there is no cached fallback, so the hand-over opens an
  unresolved item and stalls.
- [x] Preparation survives queue churn: `prefetchQueue` cancels the read-ahead
  job on every queue change, and the search for the next track was inside it.
  It now runs `NonCancellable`, so a Flow top-up or an Automix replan no longer
  takes the only prepared stream with it.
- [x] A cancellation is no longer reported as a preparation failure.

**C2. Worse on the Spotify catalogue.** — CHECKED
- The preload path calls `SourceResolver.prepareForPlayback`, which asks the
  same ranked, provider-aware candidate list playback uses. The difference on
  the Spotify catalogue was that its rows had no playable id at all (A1/A2), so
  there was nothing to prepare; that is fixed at the source.

**C3. Automix must not start a transition into a track it cannot play.**
- Not separately changed: the transition waits on `StreamChoice`'s preparation
  flag, and the preparations now finish instead of being cancelled. A guard
  that skips the effects when the incoming stream is missing would be a second
  engine behaving as if the first one could not be trusted; revisit only if the
  log still shows a transition into an unprepared item.
